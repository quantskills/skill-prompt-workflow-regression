# 给 EVO 工具工作流的下载结果评分

上一条[消息流导入](evo-log-import.md)适合单轮批量回答。这一条针对固定文件工作流，适合检查模型调用脚本处理库存、发票和汇率的结果。它读已经下载的产物，不联网，不在 EVO 发起新运行，也不执行压缩包里的 Python 文件。

## 准备文件

| 文件 | 用途 |
| --- | --- |
| 固定文件流程下载的 ZIP | 读取原来的输入、计算结果、程序和模型写的回执 |
| 任务开始前保存的冻结清单和标准答案 | 核对输入字节，给库存、金额和拒绝访问三个结果评分 |
| 单独保存的脚本审批记录 | 核对下载程序路径和 SHA256 |
| 可选的独立页面卡片文本 | 对照脚本调用的路径、运行编号和页面显示状态，仅作摘要 |

目前支持 [EVO 固定文件流程](fixed-file-workflow.md)历史复验使用的目录结构。ZIP 内只有一个运行目录，含 `bundle_manifest.json`、`solve.py`、`inputs/`、`output/result.json` 和 `output/run_receipt.json`。独立冻结清单用 `inputs/相对路径` 记录每份输入的 SHA256。不要用 ZIP 内的清单替代单独保存的冻结清单。程序检查这些材料是否相互一致，不能认证提供者身份。

## 导入并评分

在项目目录装好依赖后运行。没有卡片文本就省略 `--cards`；已有输出目录时换个新目录。

```powershell
.venv\Scripts\python scripts/score_evo_tool_workflow.py --archive "本轮下载.zip" --expected "标准答案.json" --frozen-manifest "事前冻结清单.json" --approval "审批记录.txt" --cards "页面卡片.txt" --local-replay --output "outputs/evo-tool-check"
```

打开 `report.json`。A 核对库存净变动及业务编号，B 核对发票换汇金额，C 核对权限拒绝结果，另有一项逐条核对工具、路径、列顺序和返回状态。金额按精确十进制比较，业务编号仍按字符串核对。结果算对但工具参数或顺序不符，会单独扣掉工具记录这一项。命令执行成功只表示报告已生成，是否通过要看各项结果。此命令只给单轮产物评分，不虚构新旧版本比较或发布判断。

`--local-replay` 只运行仓库内可信的检查逻辑，重新读实际文件，把每次调用的参数和本机返回数据或异常保存为 `local-tool-responses.json`。预设的一次超时和权限拒绝是测试条件。本机返回不充当 EVO 回执；不想保存本机读到的数据就省略此参数。

页面对上时，`page_card_status` 也只会是 `matched_summary_only`。缺卡片、只有一部分摘要或摘要冲突都有不同标记。包里的 `run_receipt.json` 是模型填写的文件；原始返回拿不到，就不确认后台字段或退出码，也不把会话回读当工具返回。当前这个入口不会给出「原始平台工具回执已核验」的结论。

## 真实下载包的复跑结果

使用此前 DS-V4-Pro 在 EVO 实跑的三份库存与发票核对下载包。业务输入是事前冻结的测试文件，平台脚本调用确实发生；本次没有重新调用 EVO。三份下载的输入字节和计算脚本分别对上独立冻结清单和审批散列。每轮四项都通过，最终计算运行编号及状态在三份独立页面卡片上都有对应；第二轮先失败的运行仍在报告里，第三轮原先的工具参数错误也没有从历史记录中抹掉。

本机用同一组输入复跑三次，共实际记录十五次读表调用。每轮顺序是一次预设超时、三次成功读取和一次权限拒绝；受限表没有被打开。本机结果与三份 EVO 下载产物一致。档案没有保留这三轮完整的原生 `run_script` 或 `script_status` 返回，核对数为 **0/3**。这仍不是完整工具链验收，也不能证明平台文件隔离。

原始下载包、卡片、模型回执和本机工具返回都留在本地，不进入公开仓库和压缩包。较早的错误与恢复证据见[固定流程复验](evo-fixed-workflow-20261105.md)。
