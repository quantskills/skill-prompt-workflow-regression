# 固定文件准备与交付

此前 EVO 实测中，执行模型自行编写解包、打包程序时出现读取旧脚本、工作目录判断错误和输出越界。新流程由操作者运行固定程序，模型只处理已准备好的任务，不再生成文件管理脚本。

```powershell
python scripts/task_bundle.py prepare --workspace C:/research --archive task.zip --sha256 实际SHA256 --run trial-01
python scripts/task_bundle.py pack --workspace C:/research --run trial-01
```

输入包直接放在 workspace 内。prepare 验校验值，拒绝危险路径、链接、重名成员和过大输入；目标已存在即停止，不覆盖。全部成员解到 trial-01/inputs，并保存输入哈希清单。pack 先检查清单和输入，随后只收集输入、solve.py、output/result.json、output/run_receipt.json，以及可选且明确标注的 model_transcribed_response.json。不递归收集其他输出或旧任务。结果包固定在 workspace/trial-01-results.zip，已存在即停止。

在 EVO 中，由操作者预先上传固定脚本与固定启动文件。启动文件以自身位置确定项目目录，只填冻结的包名、校验值和本轮名；模型无须找目录、编写解包程序或推断工作目录。先完成准备再发任务；完成模型计算与回执核对后，再由操作者打包。启动文件和固定程序也要保留哈希，不能只验证任务包。

上传前确认当前文件树选中的目录：EVO 可能把文件放到当前目录，而非项目根。上传后先打开启动文件确认完整路径，再运行；误放文件不运行，不静默清理历史文件。任务白名单逐项写完整相对路径，例如 trial-01/inputs/TASK.md、trial-01/inputs/CONTRACT.md，不用仅在第一项写 inputs/ 的缩写形式。

库存类示例可使用 scripts/business_ids.py：duplicate_ids 和 missing_ids 一律保留源 event 字符串，前导零不能丢失，行号不是业务编号。同编号不同内容停止，空数量记录对应事件编号，不用 0 填补。辅助函数只处理已由授权工具返回的行，不读取文件。

金额任务需另写清楚：发票同币种允许多笔并累加，不能当重复冲突；汇率表同币种不同数值才是冲突。不要只写“遇到冲突停止”而不定义冲突对象。冻结题目后发现歧义，应记录并在下一批新任务中修订，不能悄悄更换原题及答案。

## 固定计算与工具调用

库存、发票和权限核对可把 `scripts/fixed_checks.py`、`scripts/business_ids.py` 和任务自带的读表程序一起冻结。用 `run_checks(read_table, audit_log)` 生成结果。金额累计过程中保留十进制数，最后统一转成字符串；不接收二进制浮点数，也不把缺失汇率填零。固定程序校验表名和列顺序，出现无关字段时在读表之前报错。只对库存的首次超时重试一次，权限拒绝不重试。

若试验目标是检查固定工作流，操作者预先部署入口脚本。模型在恢复后只需运行它并查询状态。入口程序写结果后打印文件路径、摘要和哈希，模型不再用通用读文件工具打开结果；操作者独立下载验证。运行和查状态分别使用各自的参数，不从一条调用复制无关字段。不要为了省一步，将应用侧读表校验说成 EVO 通用工具拦截或文件隔离。

模型回执可单独保存为对话转录。平台原始记录、页面工具摘要、模型转录分开存放；平台没有可验证的原始记录时标明未取得。不拿应用审计或脚本打印的哈希补写平台退出码。

## 仍然存在的限制

这些固定脚本是可靠性措施，不是权限隔离。EVO 仍可能允许模型用普通工具读取旧文件或改写脚本；每轮新会话也共享项目。涉及敏感数据时，必须由平台提供真正的读取限制，不能把本流程当保密保证。校验清单没有外部签名，不能抵抗有权限同时改写清单和输入的主体。

模型生成回执不是平台原始响应。页面编号和状态可独立核对，但只取得摘要时，不能宣称完整原始字段已验证。平台复验必须另留实际读取轨迹、失败记录和证据缺口。本机测试通过不代表 EVO 行为已通过。
