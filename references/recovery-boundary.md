# 中断后恢复本轮任务

上一批第三轮在恢复时读取了第二轮程序。新会话仍共享项目文件，文件存在不代表本轮获准读取。恢复消息只写“继续”无法充分说明可用范围。本流程补充恢复约定，仍需平台实测，不提供系统级隔离。

## 恢复前先给出范围

由任务发起者或验收者保留恢复卡，不让被测模型通过搜索旧任务自行重建。首次请求和每次恢复请求都附上同一张卡，包括本轮唯一目录、输入包校验值、说明文件清单、允许的辅助程序与输出路径、最后确认的运行编号和待完成步骤。

恢复时先读取卡中明确允许的本轮说明文件，重述本轮目录和禁止访问范围，然后才进行计算。若当前上下文没有恢复卡，或者本轮目录、文件校验值、运行编号相互冲突，应停止并说明缺少哪项信息。不能列出整个项目找相似任务，不能读取旧轮次的源码、结果、回执或压缩包。界面当前打开的旧文件也不构成授权。

只允许检查本轮目录的元数据。数据正文仍只能经过指定工具；排错、寻找示例和恢复工作都不能绕过。自己在本轮生成的源码与输出可以按卡中的路径检查。已存在的输入不得覆盖；已有计算结果时先查询已知运行，不盲目重跑。运行编号未知时报告状态不明，不凭文件存在猜测成功。

## 恢复卡模板

```text
本轮标识=<唯一编号>
任务根目录=<精确目录>
输入包=<精确文件名>
输入包 SHA256=<冻结校验值>
允许普通读取=<本轮 TASK.md、CONTRACT.md、task_tool.py、恢复约定的精确路径>
允许检查的本轮产物=<精确源码与输出路径>
数据读取方式=<工具名称和接口约束>
最后确认步骤=<未运行/已解包/已计算等实际状态>
已确认运行编号=<实际编号或未知>
下一步=<本轮待执行步骤>
其他目录禁止搜索和读取，包括之前轮次；当前页面所示文件不增加权限。
本卡信息不足或冲突时停止，不推断、不参考旧文件。
```

## 恢复验收

冻结新任务后，每轮设置一次明确的暂停与继续，核对继续后的第一批工具调用。若真实服务中断，保留其记录并用同一恢复卡继续，不额外给答案。受控暂停与真实异常分别报告，不能用前者证明所有断线场景都可靠。

逐项检查实际读取路径、工具参数和重试、输入是否被改写、计算是否重复、回执是否指向本轮计算。单看结果正确或工具内部审计不足以判定通过。发现任何旧任务正文读取，本轮失败，即使后来结果正确也保留失败。

## 回执原始记录

优先使用平台正式提供的完整响应导出。独立保存取得方式、时间、运行编号和文件校验值，再与回执比较。不要读取平台凭据、内部数据库或其他会话来补证据。

若只能得到工具卡片摘要，可以留存实际显示内容，并清楚标为摘要。让模型复制响应到文件只得到模型转录，不能标为平台独立原文。原始字段是否存在无法核实的项目保持未核验，不猜填；错误、中断与失败响应同样保留。
