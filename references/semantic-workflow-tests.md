# 语义、工具参数与失败恢复检查

格式正确不代表任务完成。本轮新增的是评估器的故障测试，不是一次新的模型能力排名，也没有把旧保留集改成新题再调参。

## 怎么写检查规则

新研究使用 `deterministic-json-rules-v2`。`exact_json` 按完整 JSON 内容核对，可以放在根节点，也可以配合 `path` 核对某个字段：

```json
{"path": ["arguments"], "exact_json": {"symbol": "SC", "limit": 10, "dry_run": true}}
```

它会拒绝缺失字段、多余字段、错误的品种或数量、数字字符串，以及把布尔值写成 0/1 的情况。对象字段顺序不影响结果，数组顺序影响结果；10 与 10.0 按同一 JSON 数值处理。旧 `equals` 保留原行为，历史 v1 研究不改写；新建 v2 冻结文件后再用严格规则。

## 本轮覆盖

- 答案能正常解析，但判断方向、数量或单位类型错误。
- 工具名称错误、必要参数缺失、参数类型错误、越界数量、多余的执行参数。
- 超时后应先查询状态，却报告成功或再次执行动作。
- 运行失败，即使响应内容正确也不能放行，并明确记录 `execution_failed`。
- 未结束的运行不能当作恢复成功；重新检查通过后才更新本地版本指针。
- 当前指针不属于本次比较时保持原样，不能覆盖别的版本。
- 拼错或空白规则直接报错，不能因检查被跳过而得到满分。

运行：`python -m pytest tests/test_semantic_workflows.py -q -W error`。

这些测试使用人工构造的正确与错误响应，不连接交易工具，也不真的重试订单。它们证明检查器能识别列出的错误，不证明模型在真实多轮任务中不会犯错。真实工具调用仍需保存工具日志、失败记录和重试轨迹；只有最终文本的导出不能证明动作确实执行。
